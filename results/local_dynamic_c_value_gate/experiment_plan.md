# Predeclared limited Local Dynamic-C value gate

This plan is frozen before GPU inference. Question: under two 60-s alternating K6/K7 traces, does current-K lookup (K6:C2; K7:C4) reduce DMR against tested fixed C2/C4? It is a limited pilot, not a final controller. Static S(C) uses the unchanged valid5 input, formula (6*mean_DMR(K6,C)+7*mean_DMR(K7,C))/13; full values and input hashes are recorded. C4 minimizes this descriptive score; it is not a forecast, bound, or claim about every fixed configuration in the dynamic trace.

## Execution

Exactly 2 four-second smoke acquisitions, FIXED_C4 then lookup, followed only after both PASS by 30 primary acquisitions. Trace A is K6,K7,K6,K7; B is K7,K6,K7,K6. Phases are 15 s, source tick 0..1799, 30 FPS per active stream. First six canonical sources use samples 0..1799; seventh consumes 0..899 across its active intervals without rewind. Each primary expects 11,700 frames (5,400 K6 + 6,300 K7); each smoke expects 780. Logical arrivals use integer absolute rational offsets. Delayed producer still generates all requests. Trace-budget completion, full drain, joined threads and pipeline NULL are required; natural EOS is separately recorded, not required or synthesized.

All policies use one engine and P=4 independent context/stream/private pinned+device buffer workers. Frozen infer/preprocessing/decode functions are imported unchanged. Unlike Formal, FIXED_C2 retains four workers/resources. New condition-variable admission and logging are shared by all policies. Admission counter increments atomically with cap check/FIFO ready removal; counter decrements at completion publication, while A_service is reconstructed from [s,c). No GPU wait occurs inside the admission lock. Cap decreases do not preempt existing requests; counter>=C prohibits new admission. s is at the end of accounting, as in Formal. Slot reservation is the admission linearization point immediately before s; boundary eligibility is checked against that observed monotonic time.

Controller receives current K only. Scheduler-owned boundary observer updates K, notifies controller and applies cap under the same lock used for admission. Due boundary checks also run in admission and producer paths. Initial K/C is set before requests. Logical/notification/apply/reservation/publication times are separate. Overdue intermediate K notifications are preserved with superseded_cap_decision events; only the latest cap is installed, without pretending earlier decisions admitted work. No retrospective K/C rollback for late arrivals. Fixed policies traverse the same notifications and log cap holds.

Warm-up inference count=0, no measured sample exclusions, inter-acquisition deliberate cooldown=0, all inherited from recorded Formal configuration. Runtime watchdog=300 s and parent process timeout=420 s are retained. No arbitrary 10 s cooldown is introduced because an explicit NONE already exists. Environment is MAXN, clocks unlocked, CUDA Graph OFF, B=1, canonical engine auxiliary streams unchanged. Current video hashes are current evidence, not claims about historical acquisition hashes.

Order: Python random.Random (MT19937), seed 20260913. Fixed six-combination list shuffled once, shifts 0..5 shuffled with the same RNG, first five distinct shifts used. Each combination occupies five different positions, early/middle/late counts a permutation of 1/2/2; this does not fully balance all carryover effects. Exact 30-row order is immutable. Every acquisition is a fresh process; no phase cooldown/reset.

## Statistics and gate

Primary DMR uses all 11,700 frames with exact (c-a)*30>1e9, including startup, late arrivals and drain. Experimental unit=run. Five repeated metrics use mean and sample SD ddof=1; local P95/P99 are computed per run, then aggregated, never pooled or added across components. Completed FPS=11700/((last_c-t0)/1e9), drain=max(0,last_c-t0-60s). Paired Δ2/Δ4=fixed DMR−lookup DMR in the same execution round. Report all five differences, mean/SD, positive-round count, >=1pp indicator, and relative reduction=100*(fixed mean−lookup mean)/fixed mean (N/A if zero). Same-round pairing is a block comparison, not identical runtime state.

PROMISING_FOR_NEXT_STAGE requires both Δ means>=0.5pp and >=4/5 positive differences for both baselines in both traces. Otherwise SMALL_OR_INCONSISTENT_GAIN if at least one trace has lookup mean below both fixed means; otherwise NO_OBSERVED_ADVANTAGE_IN_TESTED_TRACES. Any incomplete validity gives INCONCLUSIVE_VALIDITY. These are predeclared engineering criteria, not statistical significance or general superiority. Reporting >=1pp/relative reduction does not change gate.

Secondary windows are fixed to arrival startup [0,1), transition [b,b+1) and remainder [b+1,b+15), b=15/30/45; initial remainder [1,15). One second is not assumed settling time. K6/K7 cohorts retain arrival phase/deadline. Transition records separate already service, ready, generated pre-ready and generated-after-apply requests. For decreases record A_service and counter thresholds <=C and <C separately from first admission. Negative transition-window differences are observed additional misses, not isolated causal switching costs. Queue/service, front-end/startup and carried backlog are all considered.

No residual controller, future prediction, dynamic scope extension, server/edge, partitioning, accuracy, profiler or additional GPU run is authorized. First integrity/exit/GPU/teardown/watchdog/environment failure halts the campaign. Partial/failing artifacts and actual child status are preserved. Persistent start_new_session management, flock, atomic state and append-only progress prevent duplicate execution. Unknown interrupted rows become ABORTED with no retry. Only untouched rows in this exact frozen plan could resume. No automatic system restart.

## Preservation

Original Formal runtime and data are read-only. Figure relocation changes only 28 exact paths/captions with byte/hash equality; reports with historical links and old reproduction outputs are documented rather than rewritten. Additional controller/event bookkeeping can have overhead, shared across the new policies; Formal metrics are not the primary comparator. Temperatures/clocks/processes are sampled only between acquisitions, so unobserved within-run hardware variation cannot be causally identified.
