# EDGE_INFLIGHT_ROBUSTNESS02 preregistration

This is an Edge-only E48 temporal-placement sensitivity test. It asks whether a substantial part of E48 ALIGNED timely-service loss under the prior C_E=1 server is sensitive to server-side inference concurrency. It is not a maximum-capacity or concurrency optimization study. Local C_L=3 is frozen for later main experiments and is not exercised here.

The frozen production input is eight 30-FPS streams, RAW640 (691,200 bytes/frame), RT-DETR Warehouse TensorRT engine, B=1, D=100 ms, 30-second active sessions, 10-second minimum idle after drain. The existing canonical q6 mask and phases define E48 ALIGNED ([0]×8) and STAGGERED ([0,1,2,3,4,5,6,7]); source timestamps, sender, protocol, queue policy, and frame identities remain unchanged. The sole server treatment is C_E=1 or 2 independent B=1 TensorRT jobs. C_E=2 is not batching.

The eight measured conditions run in this exact order: CE1-R1-ALIGNED, CE1-R1-STAGGERED, CE2-R1-ALIGNED, CE2-R1-STAGGERED, CE2-R2-STAGGERED, CE2-R2-ALIGNED, CE1-R2-STAGGERED, CE1-R2-ALIGNED. With METHOD B the server process is restarted at the two C_E boundaries while one Thor CPU pin remains active across all three stages. No measured run is retried or overwritten. Every session has the existing 50-inference-per-worker server warmup before READY; there is no scored warmup session.

For each repeat j, Delta_j = overall_TIR(C_E=2, ALIGNED, j) − overall_TIR(C_E=1, ALIGNED, j). The +0.10 threshold is an **absolute TIR-point increase**, not a relative percentage. If both Delta_j ≥ 0.10, the verdict is `EDGE_BURST_CONCURRENCY_SENSITIVE` and C_E=2 is selected. If both Delta_j < 0.10, the verdict is `EDGE_BURST_CONCURRENCY_ROBUST` and C_E=1 remains selected. A split result is `EDGE_C_REPEAT_AMBIGUOUS` with no selection and no automatic third repeat. STAGGERED, worst-stream TIR, per-stream TIR, and dispatch-position diagnostics are supporting evidence only.

All eight runs require frozen source/mask fidelity, exact terminal and server accounting, current CPU pin evidence, Edge worker/context cardinality, successful drain/cleanup, and no protocol/network setup error or automatic retry. The first INVALID run stops subsequent measured work. Setup/network failure is INVALID, not a performance failure. Analysis runs only after CPU restore PASS and raw Edge transfer. Earlier C_E=1 results remain valid for their deployment configuration regardless of this sensitivity verdict.

Robustness01 stopped INVALID before active start because its new backend factory omitted the TensorRT module binding required by ContextWorker; it supplied no performance evidence. Robustness02 retains the scientific design and changes only this runtime integration binding. A separate Edge-local, non-measured, real TensorRT/CUDA C_E=1 and C_E=2 backend smoke from the exact frozen bundle is required before the Thor execution check and any measured run. CPU-only synthetic PASS alone cannot establish measured readiness. No EDGE_INFLIGHT_ROBUSTNESS02 measured outcome has been observed.
