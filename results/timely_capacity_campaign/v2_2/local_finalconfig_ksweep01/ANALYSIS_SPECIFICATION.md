# Formal analysis specification

The measured cohort contains exactly the 40 run IDs in `session_plan.json`; each K=1..8 has R1..R5. The analyzer uses only the new campaign's raw frame and phase traces after CPU restore PASS. Synthetic validation files are excluded. Every run must pass inherited timestamp, phase/CUDA-event, terminal, Edge-off, GPU frequency, CPU, process, drain, exact K-source, and C_L=3 checks. The first INVALID stops execution; an incomplete cohort is not summarized as a completed 40-run baseline.

For a run, active completed FPS counts completion timestamps within the 60-s active interval divided by 60. Timely FPS uses the admitted source cohort and 100-ms deadline, including completion after active end when timely. Overall TIR divides timely Local completions by K×30×60 source frames. Worst-stream TIR is the minimum of exactly K per-stream TIRs. Queue wait is Local ready-to-service-start; service is Local service-start-to-completion. Active concurrency is in-service Local frames (mean, time-weighted p95, peak); it must never exceed three. Warm-up is excluded. Report source count, duplicate count, active-end unfinished, drain-end unfinished, and CPU/GPU integrity for each run.

`analysis01/per_run.csv` retains all 40 run values and a JSON array of exactly K per-stream TIR records for each run. `analysis01/per_stream.csv` also reports these records in long format, with exactly K rows per run and no padded pseudo-streams. `analysis01/per_K_summary.csv` contains n=5, mean, sample SD, and R1..R5 individual values for completed FPS, overall TIR, worst-stream TIR, and timely FPS. `analysis01/provenance.json` binds the plan SHA. No sustainable-K threshold or post-hoc sixth repeat is generated by this analyzer.
