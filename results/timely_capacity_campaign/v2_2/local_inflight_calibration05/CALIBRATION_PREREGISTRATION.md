# Local in-flight Calibration05 — final C closure preregistration

No Calibration05 workload or performance outcome has been observed. Calibration05 is the sole dataset for final Local deployment C selection. Calibration01–04 remain immutable historical/compatibility evidence; their completion rates are never pooled with, averaged into, or used as repeats of Calibration05. C_L is a deployment configuration for the target K=8, 30-FPS/stream workload, not a main research decision variable.

The sole intervention is C_L∈{3,4,5,6}. Exact measured order: `LINFLIGHT05_C3_R1`, `LINFLIGHT05_C4_R1`, `LINFLIGHT05_C5_R1`, `LINFLIGHT05_C6_R1`, `LINFLIGHT05_C6_R2`, `LINFLIGHT05_C5_R2`, `LINFLIGHT05_C4_R2`, `LINFLIGHT05_C3_R2`. There are two repeats per C and no historical repeat. Each run uses the same full Local path, eight source videos at 30 FPS/stream (240 FPS total), decode/preprocess, ready queue, TensorRT engine, B=1, MAXN, CUDA Graph OFF, SpinWait OFF, TRT streams=1 per worker, GPU 1575 MHz target, pruning OFF, 60 s active interval, 30 warmup inferences per active worker, drain/completion accounting, and at least 10 s idle after cleanup. Thor's seven CPU policies are manually pinned performance/min=max 2601000 kHz and restored to schedutil/min=972000/max=2601000 kHz after success, failure or interruption, before analysis. No Edge or network inference. Expected workers/contexts/warmups are C3=3/3/90, C4=4/4/120, C5=5/5/150, C6=6/6/180.

Per-run supply classification retains the validated raw-scan definitions. `INVALID` fails measurement integrity and contributes no performance evidence; the launcher stops subsequent workload at the first INVALID. `SATURATED_VALID` requires VALID, all required source work admitted, `g_B_H > 0.5 frame/s`, and `Delta_FPS > 0.5 FPS` (raw `UNSUSTAINABLE`). `SOURCE_LIMITED` requires VALID, raw `STABLE`, and active completion ≥239.5 FPS while the full 240-FPS source is admitted. Other VALID runs are `AMBIGUOUS`. Each C's supply class requires two matching repeats. Discordant classes give `C_LEVEL_REPEAT_AMBIGUOUS` and no final C. Two `AMBIGUOUS` repeats provide no selection from that C.

Final selection uses only Calibration05 measured rows, in this hierarchy:

1. Any INVALID run: `NO_C_SELECTION_INVALID_DATA`, `C_selected=null`.
2. Mixed repeat supply classes: `C_LEVEL_REPEAT_AMBIGUOUS`, `C_selected=null`. If repeat-level closure branch or selected C conflicts with the two-repeat-mean decision, use `REPEAT_AMBIGUOUS`, `C_selected=null`. If no C is 2/2 SOURCE_LIMITED and at least one C is 2/2 AMBIGUOUS, use `REPEAT_AMBIGUOUS` with a distinct `repeat_ambiguity_kind=TWO_OF_TWO_AMBIGUOUS_SUPPLY`; do not relabel VALID data as INVALID. No third repeat is automatic.
3. If one or more C is 2/2 SOURCE_LIMITED, select the **smallest tested** such C and report `FULL_LOAD_SUSTAINABLE_C_SELECTED`. This establishes only that the selected C sustains the target 240-FPS offered workload. It does not estimate true maximum saturated capacity above 240 FPS.
4. If C3,C4,C5,C6 are all 2/2 SATURATED_VALID, let r3,r4,r5,r6 be their Calibration05 two-repeat mean active completion FPS. If `r6 > 1.02*r5`, report `FINAL_CLOSURE_NOT_REACHED`, choose no C, and only propose C7. This is the sole performance-based preregistered non-closure condition for a fully VALID, supply-class-consistent all-saturated scan. C7 is never automatic.
5. Otherwise, if all four C are 2/2 SATURATED_VALID and `r6 <= 1.02*r5`, let `rmax=max(r3,r4,r5,r6)` and select the smallest C satisfying `rC >= 0.98*rmax`. Report `FINAL_SATURATED_PLATEAU_C_SELECTED`.

The final Local in-flight limit is determined only from Calibration05 according to the frozen decision hierarchy. If Calibration05 selects C4, C5, or C6 instead of C3, the selected value will be used in the subsequent main evaluation without reverting to the earlier Calibration04 choice.

Record active completion, source/admission rates, `Delta_FPS`, `g_B_H`, supply class, queue wait, service, GPU span, host residual, active concurrency, OC3, temperature, actual GPU frequency/target fraction, CPU validity, and integrity. Queue wait, service time, GPU span, host residual and temperature characterize execution; they cannot override final C. Queue wait under saturated overload is not a direct measure of total backlog. OC3 is diagnostic only. No post-hoc weighted, knee, or composite objective is allowed.

Synthetic and historical-artifact replay tests establish structural validator/finalizer compatibility only. They do not establish C6 GPU performance, a plateau, or a final C. Only a future approved Calibration05 eight-run measured campaign can do that. A failed/interrupted namespace remains preserved; no retry, resume or overwrite is allowed.
